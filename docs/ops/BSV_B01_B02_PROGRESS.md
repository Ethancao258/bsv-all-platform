# BSV-B 独立研发进度（PR #41）

本分支仅交付 BSV-B01/B02 的只读 Excel 校验与版本差异核心，不改 PR #40 的 A 阶段分支，也不连接 CloudBase/真实员工数据/生产库。

## 已实现（代码级，可在隔离测试中验证）

- 复用现有 `bsv_v9_import` 的七表名称、固定 ID、字段读取和报价检查规则。
- 对 `.xlsx` 执行 OOXML ZIP 路径、成员、大小、CRC、宏、外部链接、嵌入对象和压缩比检查。
- 以原 Excel SHA 对比版本；重复上传同一字节返回 `IDEMPOTENT_NOOP`。
- 与上一版相比返回新增、修改字段名、待退役行及公式单元格差异；不返回配方、采购价格等字段值。
- 未登记列变化、缺失基线、数据库活动版本与基线 SHA 不一致时拒绝进入审批；缺行仅报 `PENDING_RETIRE`，不自动删除。
- 整条功能目前是库级 `PREVIEW_ONLY`，没有 HTTP 页面、PG事务写入、审批签名或正式账户鉴权。

## 进入 PostgreSQL 写入前的门槛

现有 `bsv_catalog_import.py` 只接受已经生成并按当前数据契约校验的 WorkBuddy 包 ZIP；目前没有应用内原始 `.xlsx` 转规范包的生成路径。它的签名审批绑定执行 OS 用户，不构成集团身份服务里的双人BM审批。不能把上述门槛改成单一网页调用，也不能让上传服务绕过既有审批签名。因此，本分支不宣称 B02 上传到提交闭环完成。

下一步需要基于 `config/data-contracts.json` 和 WorkBuddy 生成器审查规范的转换器，接入集团现有服务端身份与双人审批动作，再让该服务调用现有事务 importer；任何字段变动须先更新注册契约，默认不启用删除。

BSV-B03 的逐项编辑页面、B04 正式员工注册、B05 资格/排班/设备、B06 旧库迁移、B07 真实经营和 B08 运营验收均未包含在此分支。状态：`NOT_IMPLEMENTED`。

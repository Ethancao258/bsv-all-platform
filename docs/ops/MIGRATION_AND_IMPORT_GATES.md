# 云数据库初始化与导入的强制验收门槛

**阶段G0 只读盘点**：真实云环境ID、PG引擎/区域、existing schemas、10产品表名主键、是否存在 `bsv_stores`、表内行数、RLS、Grant、平台迁移历史、备份情况；不可假设用户反馈等于现场核验。

**阶段G1 数据恢复与安全**：创建或找到可执行恢复的加密备份；在独立环境恢复并读取样本；对原表数据校验和、表结构差异、同名冲突建立基线；验证数据库权限和隐私处理。

**阶段G2 设计与预览**：先锁定对象字典、FK、作用域、资金/时间类型、软删除/历史事件规则。正式 DDL 由CloudBase官方 `planMigration` 预览；不能把前版40/39表模板直接执行。

**阶段G3 小步落地**：先组织+身份授权+审计+发布版本，再培训+考核与员工，后订单/支付/库存/中央供应/营销/资本。每一步单独版本、测试与回退；不设无人监督生产写权限。

**阶段G4 原始资料导入**：先私有原件清单 → 解析staging → 映射与校验 → 异常隔离 → 批次审批 → 可回溯正式入库。用户/员工真实身份、资金及合同要按实际合法权限单独处理。

**阶段G5 联调**：一店完整订单与真实支付、断网重连去重、员工权限变化、电子菜单审核发布、异常督查与回退；未通过不能替换现有生产收款系统。

通过条件必须附工具日志/SQL返回值/计数及Git SHA，绝对不能只写“部署成功”。

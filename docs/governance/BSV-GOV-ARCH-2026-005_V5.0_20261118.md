## 一、公司定位与经营逻辑

### 1.1 公司是什么

BSV当前以**酒饮与餐饮现场服务**为核心业务。公司通过组织人员、开发和采购产品、执行标准制作、提供现场接待与顾客体验、完成销售及售后，获得营业收入和经营现金流。

顾客购买的不是某个内部部门、数据库或广告行为，而是**可被感知、可被交付、值得再次购买的产品与服务**。公司的全部内部活动，最终必须服务于稳定交付、顾客选择与可持续盈利。

### 1.2 当前经营组织与服务边界

| 项目 | 当前公司情况 |
|---|---|
| 经营主体 | 北京密聚玖餐饮管理有限责任公司 |
| 经营品牌 | BAR ST. VINCENT（BSV）；旗下使用文森特精酿酒馆等经营名称 |
| 门店网络 | 北京现有五个经营点位，已知覆盖密云、顺义、通州；包括鸡尾酒现场服务及精酿、台球等合作业态 |
| 收入基础 | 向消费者销售酒饮、餐食及相关现场服务；部分合作业务按合同约定结算，不能等同于直营收入 |
| 组织形态 | 公司总部制定共享标准和支撑规则，各门店承担一线交付；业务功能与现有人数、岗位编制不必一一对应 |
| 发展方向 | 先使门店自洽运行，再验证中央共享效率、营销增长及外部合作，最后在现金与监管许可范围内进行资本配置 |

**核算原则：** 直营、合作、第三方授权及可能的未来金融业务应当分别定义收入归属、成本口径、合同主体与风险责任。本文件不把不同业态的全部流水直接合并解释为公司的可分配利润。

### 1.3 企业总模型

> **BSV1保证经营与交付；BSV2提高效率、扩大需求并独立纠错；BSV3在经营安全的前提下配置资本。**

三者是**同一家企业的三个经营功能圈层**，不是三个相互替代的软件版本、三家独立公司，也不是按部门编制或法定主体机械划分的三个组织。

| 圈层 | 正式名称 | 解决的根本问题 | 经济作用 | 判断是否有效 |
|---|---|---|---|---|
| **BSV1** | **基础经营与服务交付系统** | 没有总部增强支持，门店还能否在安全、合规条件下完成经营交易？ | 生存、稳定交付、基础收入 | 门店能独立采购、制作、服务、收款、核算并处理日常异常 |
| **BSV2** | **经营增强、独立纠错与外部增长系统** | 怎样让BSV1更容易被发现、效率更高、错误更少，并将能力向外输出？ | 提升贡献、扩张收益、降低系统性损失 | 有证据证明增量贡献、效率提升、纠错效果或外部合同价值 |
| **BSV3** | **资本治理与长期价值系统** | 企业产生的可配置资本应如何留存、融资、投资与管理风险？ | 资本增值、风险分散、资本化 | 不危及运营偿付能力，资本使用合法且经核算创造长期价值 |

### 1.4 分层原则

1. **以具体业务活动的目的与失效后果分层，不以部门名称分层。** 同一个岗位可以同时执行BSV1与BSV2任务，但责任、数据和考核分别归属。
2. **BSV1必须具备最低可运行能力。** 增强工具中断时，可以减少可售产品、采用替代供应或暂停非必要活动，但不得违反许可、质量及安全底线。
3. **BSV2是可替换的能力增强，不应成为无法回退的隐性单点依赖。** 对外合同、食品安全和法律义务不因系统分层而自动免除。
4. **BSV3使用经核算且可合法支配的资本。** 工资、租金、采购、税费、偿债和必要经营备付金不得与投资资金混同。
5. **所有圈层使用同一公司级对象定义与数据治理制度。** 数据统一不代表权限公开，更不代表法律主体、客户和敏感数据可以混同。

## 二、BSV1｜基础经营与服务交付系统

**使命：** 使门店在不依赖总部中央配送、专项广告投放或独立外部督查的情况下，仍然能够以经批准的最低服务组合完成合法、可靠的经营。

### 2.1 BSV1完整业务闭环

**基础需求识别 → 产品研发与制作标准 → 人员招聘与训练 → 原料采购与验收 → 门店制作与服务 → 顾客介绍与交易 → 收款、对账与售后 → 经营复盘、日常检查与纠偏 → 下一轮经营。**

以上任一环节缺失，公司都不能被认定为具备完整的基础经营系统。

### 2.2 BSV1能力与组织职责

| 功能单元 | 必须承担的工作 | 关键业务记录/交付成果 |
|---|---|---|
| **经营管理** | 经营决策、门店目标、岗位责任、授权、排班协调、标准发布、异常升级、持续改进 | 岗位责任、制度、经营记录、风险及改进事项 |
| **人力与员工体系** | 员工唯一ID、招聘、劳动/合作关系、任职权限、排班考勤、培训、服务与技能考核、绩效、交接和退出 | 员工ID、任职状态、培训记录、考勤、考核与交接记录 |
| **产品研发与标准** | 顾客反馈整理、鸡尾酒/食品/预调原料研发、配方、故事、风味、规格、成本测算、制作方法、版本审批 | 产品ID、配方版本、制作SOP、原料需求与研发记录 |
| **基础采购与库存** | 门店可独立采购、原料验收、储存、盘点、成本与损耗记录、备用供应渠道管理 | 物料ID、采购及验收记录、库存、供应商信息 |
| **门店制作与服务** | 自制果汁/糖浆/预调液、现场调制、食品安全、设备使用、开闭店、迎宾、酒单介绍、结账、投诉与复购服务 | 出品记录、质量检查、交易单、投诉处理 |
| **基础销售与员工推广** | 保持菜单、地址、营业信息和顾客咨询入口可用；员工履行岗位内个人服务形象展示、门店官方账号内容协作及必要的日常推广任务 | 菜单、对客信息、员工执行记录、顾客反馈 |
| **日常财务与合规** | 收银、订单、采购付款、薪酬、房租、对账、经营利润与现金流、税务、证照及日常风险检查 | 订单、收支、对账、报税及经营报表 |
| **基础数字系统** | 门店出品与收款、员工权限、标准查询、产品和门店身份、基础备份、离线运行与数据恢复 | 统一ID、权限、业务记录、离线数据、同步状态 |

**特别规定：** 员工参与推广属于BSV1员工岗位工作的一部分；**专门负责提升曝光、投放预算、策划大型活动及跨店获客的市场营销部门属于BSV2**。使用员工个人账号、肖像或个人信息，应遵守合法约定与授权，不得将个人私人资源视为公司当然拥有的资产。

**组织口径：** 上表定义的是公司必须覆盖的功能，不意味着当前已经设置八个独立部门或必须立刻增加八个管理职位。可以兼岗，但每项职责都必须落实到被授权岗位。

### 2.3 BSV1最低运行标准

每家门店至少应具备：

- 可执行且已批准的**基础可售菜单**、完整配方及制作说明；
- 能执行对应工作的合格人员、排班与替补机制；
- 不依赖中央配送的合规采购和必要自制路径；
- 可用的营业信息、顾客接待、订单、收款及对账方式；
- 食品安全、设备、证照和质量底线；
- 中断时可执行的停卖、降级和恢复操作。

**最低运行不等于维持全部SKU或原有销售额。** 如不能满足安全、许可或合法用工条件，必须停止受影响工序或营业，不得以“保证独立生存”为由冒险继续经营。

## 三、BSV2｜经营增强、独立纠错与外部增长系统

**使命：** 在BSV1已经能够完成基础经营的前提下，通过更专业的营销、集中供应、独立检查及外部合作，创造可以核算的增量价值。

### 3.1 BSV2能力与组织职责

| 功能单元 | 主要责任 | 与BSV1的界限 | 评价结果 |
|---|---|---|---|
| **市场营销与增长** | 公司级品牌传播、投放、内容策略、美团/抖音等平台运营、跨店活动、渠道引流、曝光增长与获客分析 | 不替代员工的基础服务展示和官方账号日常协作；不垄断产品配方与制作标准 | 真实新增到店、有效询价、增量贡献、获客成本 |
| **中央供应与共享服务** | 跨店集中采购、统一预调生产、包装、批次、仓储、物流、统一配送、共享设备和供应效率优化 | 不替代BSV1门店可独立采购、制作和安全降级的能力 | 同等交付标准下的总成本差、缺货率、损耗、稳定性 |
| **独立督查与纠错** | 非日常执行线的抽查、神秘顾客、外部质量复核、跨店问题识别、整改效果复验 | 不取代BSV1店长日常检查、员工考核和内部控制 | 重复问题减少、整改闭环、重大风险发现 |
| **外部合作与业务扩张** | 咖啡厅合作模式、异业签约、外部服务、品牌授权、管理输出、连锁拓展与合作项目开发 | 新客户或新合同获取属于BSV2；项目实际交付尽量复用BSV1 | 合同收入、扣除全部履约成本后的增量现金贡献 |
| **系统对外商业化** | 将公司已验证的经营工具和流程授权或销售给其他企业，必要时设立独立技术运营主体 | 公司自用系统的研发、维护与基础运营仍属于BSV1；对外销售及客户增长属于BSV2 | 客户付费、续约、服务成本及净贡献 |

BSV2属于企业增强层，**并不意味着每项业务都发生在公司法律主体之外**。中央供货和总部营销即使由公司内部员工执行，也属于BSV2的共享增强活动。

## 四、双轨运行制度｜一条基础腿，一条增强腿

**规则：BSV1是可独立运行的基础路径，BSV2是优先使用但须有替代机制的增强路径。任何增强效率都不能以丧失全部基础交付能力为代价。**

| 经营环节 | BSV1：基础路径 | BSV2：增强路径 | BSV2中断时的回退与限制 |
|---|---|---|---|
| **原料与供货** | 门店通过合规供应商或线上渠道独立采购并验收 | 总部统采、统一备货与跨店配送 | 回退门店采购；按库存、合规性及价格决定缩减SKU |
| **果汁、糖浆、预调酒** | 使用公司统一配方和SOP，由门店自行制作并记录 | 中央集中制作、标签、批次管理、向各门店配送 | 由合格员工按已批准门店工艺自制；不具备储运/制作条件时停卖相关产品 |
| **顾客获取** | 员工完成基础服务形象展示、门店账号岗位任务；保留真实营业信息和既有客群联系渠道 | 专业市场营销部门负责创意、专项推广、平台投放和新增曝光 | 停止专项投放，保留基础可见性、店内服务与自然客流经营；长期获客下降须及时评估 |
| **服务与产品品质** | 店长、员工按SOP自检、培训、考核和整改 | 独立督查、跨店比较、第三方验证和复核 | 回退内部质量控制；独立监督失效风险需向管理层披露 |
| **产品研究与创新** | BSV1研发、验证及维护产品、配方、故事与版本 | BSV2将批准产品组织为跨店营销与商业化项目 | 保留既有安全可售产品及基础研发；暂停需总部集中资源的推广项目 |
| **门店信息系统** | 本地出品/订单能力、获批准的离线数据与基础恢复 | 云端统一同步、跨店分析及总部效率工具 | 启动经测试的离线模式；恢复后校验同步冲突和交易完整性 |
| **收入渠道** | 依靠已开业门店向顾客交付现场服务获得收入 | 外部合作经营、授权、技术服务及新增渠道 | 暂停新增合作，不应影响既有门店基础出品；已签合同仍须履约或依法处置 |

### 4.1 跨地域规则

BSV的**配方、产品标准与人员要求可以复制到不同城市，中央实物流通不必复制**。例如，北京中央供应链无法经济且安全地覆盖距离较远的单店时，该店仍可依BSV1标准进行本地采购、制作与质量控制；是否启用当地中央仓配由BSV2根据规模、成本和监管条件另行决定。

### 4.2 回退运行的必要条件

- **有标准：** 门店能读取现行批准版本的配方、工艺、原料和质量要求。
- **有人会：** 员工接受过本地制作训练，岗位权限和责任明确。
- **有材料：** 至少存在可核验的替代采购渠道或合理备货。
- **有合规边界：** 未核准的生产、储存、运输及食品安全条件不能被“紧急回退”覆盖。
- **有记录：** 中断时间、受影响商品、替代费用、异常和恢复版本均能留痕。

**回退能力是要求建立并实测的经营制度，不表示当前每家门店已经全部通过测试。**

## 五、BSV3｜资本治理与长期价值系统

**使命：** 将企业经营形成的可支配资金和成熟能力转化为长期资本价值，同时保护BSV1的偿付能力和BSV2的正常履约。

| 功能单元 | 管理内容 | 明确边界 |
|---|---|---|
| **资金安全与资本预算** | 经营必需资金、流动性底线、投资预算、重大资本开支审批 | 日常记账、应付工资及经营现金流仍归BSV1 |
| **资本配置与投资** | 合规可支配盈余的留存、投资方向、收益/风险评估、退出决策 | 不得占用员工薪酬、税款、租金和必要营运资金 |
| **融资、股权与并购** | 股权架构、融资结构、股东权益、收购与资本合作 | 审批须考虑偿债、控制权、治理成本和长期现金流 |
| **潜在金融业务** | 远期可能依法设立的投资管理或资产管理主体 | 私募或代客管理不因本文件而获得经营资格；必须遵守独立法律主体、监管准入及资金隔离规则 |

**资本判断顺序：** 先确保履行经营义务及现金安全，再审议增长投入，最后判断可投资盈余及资本运作。不得将预测销售额或账面利润直接当作可投资现金。

## 六、组织协作与责任划分

### 6.1 三个圈层如何协作

**BSV1提供已验证的交付能力和真实经营数据。** BSV2据此选择增长、共享服务和独立复核项目；形成的客户信息、问题证据和增量结果回流BSV1，使标准及经营决策不断更新。BSV3依据经核实的经营财务与增长证据决定资本分配；资本投入不得绕过BSV1的经营与合规底线。

### 6.2 同一人可以兼岗，责任不可混淆

- **业务归属**是具体工作由哪个系统承担；**组织岗位**是实际由谁执行。
- 每项业务应明确一个主责岗位及批准权限；跨层活动明确输入、输出和交接。
- 独立督查人员不应自行批准其所审查事项的合格结果；发现重大问题应上报具有纠正授权的负责人。
- 新设科技主体或合作公司若产生独立经营活动，其自身仍需要完整的BSV1基础运营；集团对外销售该主体的服务属于BSV2商业化。

### 6.3 典型业务归属判定

| 事项 | 主责圈层 | 解释 |
|---|---|---|
| 研发一款鸡尾酒、写配方与故事 | BSV1 | 创造并维护可交付的产品本体 |
| 员工学习拍摄、协助运营门店账号 | BSV1 | 员工岗位中的基础展示和推广责任 |
| 总部策划短视频营销并购买曝光 | BSV2 | 额外获客与品牌传播 |
| 门店自行制作超级果汁 | BSV1 | 基础生产能力 |
| 总部统一制作超级果汁并配送 | BSV2 | 多店共享效率提升 |
| 店长检查出品、服务、排班 | BSV1 | 内部管理与日常质量控制 |
| 独立督查组跨店检查 | BSV2 | 独立纠错与管理复核 |
| 公司自研收银及员工系统 | BSV1 | 基础经营技术能力 |
| 将管理系统授权给外部酒吧 | BSV2 | 对外商业化 |
| 日常工资、采购付款与税务申报 | BSV1 | 经营财务 |
| 对可支配留存资金制定投资组合 | BSV3 | 资本配置 |

## 七、统一数字系统与数据库原则

**BSV ALL是公司的统一数字化与主数据治理基础设施，不是独立的第四圈层。BSV1/BSV2/BSV3是业务能力分类，不能被错误实现为三个互不联通的数据库。**

### 7.1 单一权威数据源

| 共享对象 | 全公司统一身份 | 核心使用场景 |
|---|---|---|
| 门店 | `store_id` | 收银、出品、员工、配送、营销、经营分析 |
| 员工及岗位 | `employee_id` / `role_id` | 权限、排班、培训、考核、服务责任 |
| 产品与套餐 | `product_id` / `bundle_id` | 配方、价格、菜单、营销、出品、生产 |
| 物料及配方 | `material_id` / `recipe_version` | 采购、配制、库存、成本、标签 |
| 生产及配送 | `batch_id` / `shipment_id` | 追溯、验收、异常、跨店供应 |
| 交易及价格 | `order_id` / `quote_id` | 收款、历史成交快照、对账、贡献核算 |
| 活动、督查、合作 | 各自稳定业务ID | BSV2归因、整改、合同与外部合作 |
| 资本与投资 | 独立的投资/审批ID | BSV3授权、风险与投资审计 |

**稳定ID不得与可变化的分类SKU、商品中文名或显示编码混用。** Excel、后台、门店系统、电子菜单和其他AI工具都必须引用权威对象ID。

### 7.2 系统边界

1. **统一后台与API：** 公司级公共主数据由授权的统一接口提供；所有程序复用统一字段含义、权限、版本和发布状态。
2. **门店离线能力：** 经营所需的出品、收款和已批准数据快照应具有经过验证的离线或故障降级方式；各门店订单及交易记录遵循本地隔离与可靠同步机制。
3. **公开与内部隔离：** 顾客电子菜单只能获取公开且已发布的资料，不得直接访问配方成本、员工身份、采购合同或投资信息。
4. **对外服务隔离：** 向其他企业销售系统时，采用客户/租户权限与数据隔离，不能让外部客户访问BSV内部经营信息。
5. **按业务对象扩展：** 增加产品、员工、配送、营销或资本模块时先复用主数据；有真实需求再新增表和接口，不按圈层重复建库。
6. **版本与审计：** 配方、价格、菜单、岗位制度、权限和业务接口应记录负责人、版本、生效时间和更改历史；历史订单保留成交时数据。

### 7.3 已有数字化基础与建设状态

- **CloudBase PostgreSQL：** 现有V1.2产品数据底座已形成10张业务表和对应导出包；这不等于全公司数据库已经建成或迁移可用。标准PostgreSQL的隔离恢复验证仍须完成。
- **目标部署：** 在核查资源与完成恢复验收后，逐步向现有腾讯云Lighthouse统一承载共享业务数据及受控API；不因新模块而反复拆建数据库。
- **电子菜单：** 保留EdgeOne Makers展示服务及已印刷的固定入口 **`menu.bsvm.cn`**；允许后续更换内容、接口与页面设计，不改变顾客二维码指向。
- **员工及门店程序：** 继续保留必要的本地运行和离线可用设计；统一的是数据契约与发布机制，而非强制所有功能实时联网。

## 八、经营评价与启动边界

| 圈层 | 核心指标 | 合格判断原则 |
|---|---|---|
| **BSV1** | 门店服务完成、产品合规率、制作偏差、人员覆盖、投诉处理、经营现金流、故障恢复 | 基础营业连续性及安全底线通过；真实收入能够覆盖必要经营义务 |
| **BSV2营销** | 有效曝光、询价、到店、可归因新增成交及增量贡献 | 不仅看播放量或GMV，须扣除投放、折扣、人工与对原销售的替代 |
| **BSV2供货** | 与门店自制同口径的采购、人工、包装、配送、损耗、合规及备用成本 | 集中供应确有经济或品质价值，且故障回退能力经过验证 |
| **BSV2督查** | 严重问题发现、整改完成、缺陷复发及独立性 | 不以检查次数替代实际纠错效果 |
| **BSV2合作** | 合同贡献、履约成本、质量与回款 | 合法可交付且能形成可核算的外部增量收益 |
| **BSV3** | 可投资现金、流动性、投资净回报、杠杆、资本风险 | 先保护现金安全与监管边界，再追求资本收益 |

**实施红线：** 不得为了扩张销售而牺牲食品安全、用工合规、证照条件或现金偿付能力；不得把尚未通过压力测试的回退能力写成既有事实；不得把未核准的计划当作已经实现的利润与技术成果。

## 九、对员工、投资人与开发者的统一解释

**对员工：** BSV1定义每天如何把门店经营好，以及每名员工应如何学习、服务、出品、完成基础门店账号和个人服务展示任务；BSV2由总部提供更专业的营销、供应链和独立复核支持；BSV3不介入日常出品。

**对投资人：** BSV1是门店可复制经营能力与基础现金流的来源；BSV2是在不破坏基础运营的前提下产生效率、获客、合作及管理输出收益的增强机制；BSV3负责将可分配资本转化为长期价值，同时约束财务与合规风险。三层能力的实际收益需要分别核算，不能以组织设计代替经营实证。

**对系统开发人员与AI：** 先识别业务对象、主责岗位、所属圈层、权威数据源、稳定ID和故障回退方式；然后复用BSV ALL数据和API。不得将BSV1缩减为调酒收银软件，不得将BSV2误认为新品研发系统，也不得将BSV3理解为日常财务记账。新增系统不得创建第二套产品、员工或门店身份主数据。

## 十、长期执行原则

**第一条：先活下来。** BSV1必须有能够真实完成服务交易的完整闭环。  
**第二条：两条腿走路。** BSV2提供更优的规模化路径，但BSV1保留合法、安全且经验证的替代方式。  
**第三条：增长要有增量。** 曝光、供货、督查、外部合作均以可检验的实际收益与风险改善评价。  
**第四条：资金与经营分开。** BSV3不得消耗企业赖以生存的必要现金与资源。  
**第五条：所有程序服从公司。** 统一身份、统一数据语义、统一授权接口、统一版本管理，软件只是实现企业能力的工具。  

**企业架构总定义：BSV1使公司能够生存，BSV2使公司更有效率且能够向外增长，BSV3使公司能够长期管理与配置资本。三者共同组成一家可运行、可纠错、可扩展、可持续的企业。**

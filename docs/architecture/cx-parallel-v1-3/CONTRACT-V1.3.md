# V1.3 统一操作契约
本文件为建议实施规格，不是代码、已上线接口或真实配置。上版V1.1/1.2历史保留；本版细化优先，现行已批准契约/源码约束优先于设计假定。执行者先对照最新主机基线及既有owner，原表/接口可复用即映射，不另建同义实体。只使用专属worktree和合成测试数据库，不直接改部署目录。局部更优方案不破坏契约可记录后采用；跨组、数据归属、资金语义变更提交ADR，由集成人一次冻结。所有外部账号/密钥/报价/门店映射未核验项保留null，绝不能猜测或写入Git。
OPERATIONS.json为传输无关接口合同，非新增HTTP路由清单。优先直接函数调用或现有HTTP路由映射；对外API复用现有框架OpenAPI输出，禁止把所有操作一律暴露给公网。现有已批准API可保留别名。每个条目的request/response是最小字段签名：逗号分隔 name:type，?可选；id=非空不透明字符串（兼容既有主码），s=字符串，i=整数，b=布尔，t=RFC3339 UTC，ids/ss=数组，obj/objs=明确业务投影对象/数组，items=数组[{product_id:id,quantity:i>0,options:obj?}]；obj/objs具体结构在各组数据对象和原契约核对后冻结，不允许任意字段写入。钱以整数最小货币单位+currency默认本企业已批准币种，数量正整数最小单位或已批准精确量纲。未知/缺权限不得用0替代。请求外层沿V1.1 CONTRACT：contract_version,request_id,idempotency_key(写必填),correlation_id,actor,tenant,legal_entity,store,payload；上下文由服务端可信来源生成，不接受客户端覆盖。响应统一 status OK/REJECTED/PENDING/UNKNOWN，error_code,data,retryable,correlation_id。R=不产生不可逆业务写，允许审计/缓存/查券intent；W=业务写，幂等唯一键。P=公开限频，U=客户本人，V=已授权visit，T=门店员工按岗位，Q=总部/财务明确权限，S=可信内部服务，X=外部签名回调。组合权限是候选可调用者，不表示所有都拥有同等操作权限；主体/对象/动作逐项验证。
核心对象owner: A配置/租户引导；B客户/认证（现有customer域）；C公开投影（商品权威仍catalog）；D非现金权益/存酒/计时；E归因/佣金负债；F既有POS commerce订单与visit、服务/预约；G平台核销事实；H支付/退款/储值与实际付款。共享既有所有权以config/data-ownership为准。跨组不直写其他组表、不创建第二权威库。建议仅在业务域内部使用现有事务，跨域以已有outbox或等效持久化事件、幂等接收和补偿实现。事件信封沿V1.1；实际事件名如已有等价则映射。
状态规格见STATES.json；错误映射 AUTH_REQUIRED/FORBIDDEN/TENANT_MISMATCH/INVALID_ARGUMENT/CONFLICT/IDEMPOTENCY_CONFLICT/NOT_ELIGIBLE/FEATURE_DISABLED/UNAVAILABLE/RESULT_UNKNOWN，UI解释真实下一步。不确定外部写不得自动重发或以失败释放资源。合同演示: order.submit输入visit_id=synthetic-V1, items=[{product_id:synthetic-P1,quantity:1}],quote_version=Q1；第一次成功返回order_id O1、state PENDING_STAFF；同键同参返回O1；同键改quantity=2返回IDEMPOTENCY_CONFLICT。所有例子合成。JSON不是OpenAPI完整schema，不声称已通过契约编译；集成人将与现有schema对照一次冻结嵌套字段，后续仅有证据才修订。

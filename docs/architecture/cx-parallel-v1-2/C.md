## 决策与备选
首选现有静态H5/EdgeOne菜单、guest-web/member 与 public_menu_projection；不迁移印刷域名、不重写前端框架、不直接开放POS受保护商品接口。动态购销依赖F，不需要为菜单访问每次查询云PG。菜单公开快照有审核版本、缓存ETag/哈希；私有数据永远不入公开JSON。
## 实现顺序
C1 从catalog现有稳定ID、门店注册和价格版本生成白名单投影（名称、故事、图片、标签、规格、公开价/范围、适用门店、供应状态来源）。未确认供应状态标未知，不授权销售。C2 保持原菜单入口与返回链接，新增客户门户/菜单导航/门店指南；按业态、门店feature flags隐藏未实现功能；未登录可浏览。C3 推荐使用规则：先硬过滤可供/预算/酒精限制/成分避让；标签匹配、口味与预算距离、可选择历史偏好、真实曝光校正后的热度，统一归一化评分；权重从 policy.recommendation 读取，没有样本时使用编辑精选、不伪造热度。可解释原因，用户可选完整菜单。C4 历史复购引用F/H合法订单投影，收藏保存商品ID与版本，商品下架仍保留历史名称。C5 地图使用官方导航/链接，门店坐标与找店内容配置化，不必申请定位；附近功能仅在用户授权后调用。C6 统一动态状态：到店前/预约中/到店中/离店后，优先入口按业务状态，公共导航不依赖第三方成功；图片等静态文件使用现有发布流程。 
## 交付与验收
320/390/768px手机和桌面，旧二维码可访问，禁用插件不显示死入口，售罄/价格变化/离线清晰提示，所有对客内容无成本/配方/员工信息。对比现有公开快照与商品版本；推荐不突破硬限制；无候选给明确结果；评价只由已消费事实验证。页面支持后续微信小程序复用同一API，但不要求小程序成为第一版前置。实测记录页面加载、选品到提交时间、失败率；暂无基准，不虚构提升。

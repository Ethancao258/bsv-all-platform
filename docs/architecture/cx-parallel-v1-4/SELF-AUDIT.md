# V1.3 self-audit and corrections
1. Signatures used obj/objs and allowed ambiguous payloads. V1.4 PAYLOAD-SCHEMAS.json defines closed object payloads and nested projections. Candidate policy/config bindings use typed reference IDs, not arbitrary JSON evaluation. Policy parameters are versioned domain documents, not a dynamic script.
2. Registration, custody listing, privacy request, booking list/modify, queue status, order accept, refund approval and aftersale had gaps. Add explicit operations without adding independent services. Existing 94 IDs preserved; revised semantics are candidate design changes, not breaking live endpoints. Actual transport aliases agreed once against current host.
3. coupon.cancel targeted intent rather than a specific consume attempt; now target consume_attempt_id. coupon.query and order.quote create durable IDs, treated as idempotent writes (unless host has equivalent stateless signed quote).
4. payment attempt was persisted as DISPATCHED after sending, crash gap. Persist DISPATCHING before I/O, recover by original merchant/order reference; no switch if dispatch could have happened. Same applies to payout and coupon. Payment launch data is handled by adapter-specific client launch contract; no arbitrary object forwarded from business API.
5. Existing E accrual formula assumes a single payment or uses combined facts. Add exact aggregate and refund allocation rules in E; H owns money, F owns order, E owns accrual; historical policy pinned.
6. Feature count was used as proxy for completeness; now 192 rows each have an observable acceptance target and operation/owner or UI-only path. NOT_RUN by default. No global-optimum claim or unnecessary new microservices.
7. Real configuration, schemas and latest host still unverified; no fabricated authorization. Unconfirmed fields stay null, and current production owner map overrides candidate schema. No deployment until relevant approvals.

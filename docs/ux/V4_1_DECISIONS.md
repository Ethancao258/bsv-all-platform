# V4.1 · 操作与边界审查

基线为 PR #10 部署版本。以下是工程设计的反例检查，验收证据单独登记在 `CURRENT_STATE.md`、CI 和主机回执。

| 视角 | 优先处理的反例 | 判定 |
|---|---|---|
| 门店一线与暗场 | 同一台设备换员工后沿用上一位员工的记录 | 当前统一会话与设备、班次重新核对。订单审计能回到同一 TR、门店及当班事实 |
| 触屏与响应式 | 手机软键盘、横屏、文字放大遮住确认动作 | 对话框有独立滚动和键盘焦点。底栏占位避开内容，按视口测试 |
| 新员工学习负担 | 一开始显示数据库或英文 ACL | 工作台先显示今天的班次、下一步、为何不能操作，可展开查看技术详情 |
| 成人培训 | 看完视频直接获得高风险权限 | 学完、理论和实操是独立事实。独立审核和指定门店证据齐全才形成凭证 |
| 兼职排班 | 两家店在相同时段给同一自然人排班 | 使用带偏移的时间戳比较实际区间。保留员工确认，失去资格标记待重排 |
| 权威数据 | 给同一个员工额外分配门店永久号 | 人员统一用 TR。POS 局部引用服务于 SQLite 外键及历史，权威归属仍在同一注册表 |
| 零信任 | 前端切换门店即可扩大权限 | 服务端检查任职、课程版本、实操、授权、已确认当班和注册设备。依赖不可用时拒绝写入 |
| 信息安全与隐私 | 视频原件或员工合同进入公开菜单、Git 和隔离测试 | 文件授权独立验证。预检仅接收允许字段，真实资料和正式媒体导入等待批准 |
| SRE 与恢复 | 失败发布回退时反删新表或覆盖旧订单 | 只允许指定的隔离前向迁移。切换前备份，回退代码时保留数据，主机复验与 CI 分开 |
| 财务与试点 | 未付款测试订单被计为已收款 | 隔离环境只保存未付款订单，正式收款和中央 D/E 写入分别阻断 |

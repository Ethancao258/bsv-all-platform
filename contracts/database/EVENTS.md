# DB 预检事件、唯一键与同步边界

沿用既有 [API 与事件契约](../API_AND_EVENTS.md)。合并或补传时必须携带不可变 `event_id`、`source_system`、`source_event_id`、经认证的 `actor_subject_id`、法人、门店、业务实体键、版本、UTC 发生时间、服务端接收时间与 schema 版本。事件由源权威服务发出，不能由调用方覆盖 actor。旧来源保留 `(source_system, source_event_id)`，中央写入采用适用法人和经过认证的 actor scope 加请求 ID 防重。同请求同载荷返回第一次结果，同请求异载荷隔离。

| 事件和写入责任 | 事务及冲突边界 |
|---|---|
| 人员颁发、授权或撤权 | A 锁定永久 TR 分配，阶段共用后缀，撤权实时查 A。B 只读参考，LOCAL 仅受控恢复 |
| 订单提交、出品及送达 | 保留历史 `order_id`，金额用整数最小单位，绑定提交时商品及版本；调账另记事件 |
| 付款确认 | 仅经验证的机构事件号唯一，模拟结账和本地订单永不产生真收款事件 |
| 配送发货、收货及库存变动 | request + 版本 + 包装状态防重；D 同事务过账；发 10 收 9 后留 1 件在途。物料和库位由权威服务解析 |
| 库存观察 | 五档是观察。授权调账须生成独立、可审计的库存事务 |
| 自检、独立复核和整改 | E 写检查和审批，执行者、受检者与独立审批权分离。审批事务按资源验证法人/门店 |
| 产品公开发布 | 发布记录和快照版本可追溯；顾客端仅展示白名单字段，订单中央核价 |

SQLite 本机订单和操作日志是来源证据。未验证跨设备冲突、重放和签名之前，不允许后台自动把旧 POS SQLite 写到生产。供货队列只可由原员工在同授权范围重放；失去授权、变更作用域、版本不同和异载荷转人工隔离。保留请求与审计，重试不签发新 ID；数据库恢复后的缺口先核对再补传。

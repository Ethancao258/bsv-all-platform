# PG17 预检及生产迁移门槛

## 可重复验证

从干净 Git 检出，以 Python 3.12 安装 services/api/identity/requirements.lock、playwright==1.62.0、jsonschema==4.26.0 和 Chromium，运行 `bash tests/db_preflight/check.sh`。该脚本启动一次性 loopback PG17，先跑既有身份上/下/重建迁移和加密恢复，再在同一实例的独立演练 schema/库承载消费端测试。运行 POS 与身份真实 HTTP、供货 FastAPI 请求和 PG D/E 测试事务、菜单实际静态 HTTP 与 Chromium。D/E 与组织仍使用受控合成替身，POS 使用本地 SQLite，同一生产物理数据库连接未验证。完成后自动销毁容器和临时目录；只有显式 `--update` 才更新仓库中的字段字典。测试不需要真实密码。

## 阶段及准入条件

1. **G0 真实只读**。读取实例身份、引擎版本、区域和 HTTP/数据库授权范围。按既有审计脚本逐次执行元数据 SELECT。对已报告十张产品表逐表确认 schema/列/类型、默认值、PK/唯一、FK、CHECK、触发器、索引和权限。核查 bsv_stores 的存在、门店码和法人归属，及员工/资格/订单/支付/库存/审计表是否已存在；只读取必要脱敏计数及冲突摘要。核查 RLS 与服务角色、CloudBase Auth issuer/audience/JWKS、官方迁移历史及执行授权。
2. **G1 恢复**。取得快照/PITR 覆盖时间、RPO/RTO、KMS 与恢复权限，取得真实备份在隔离目标恢复的证据。核对 schema 哈希、总量与业务金额、孤立外键、不同门店余额及审计。无恢复验证不进入生产评审。
3. **候选前向升级**。先冻结跨系统 ID 映射和权限矩阵，接着在恢复到隔离环境的脱敏数据上扩展列/约束、回填、核对，最后才切换单一写入者。现有 CSV/V9 与 POS SQLite 先作只读对账和异常报告。候选 SQL 仅见 contracts/identity 与 contracts/supply；pytest 质检 fixture 不编入真实迁移。正式 DDL 仅在 G0/G1 后，经审批提交 CloudBase 官方版本和 plan/apply 证据。不得复制 Alembic 账本到云端。
4. **兼容校验**。前后按法人和门店比对行数、金额整数分、库存守恒、唯一命令、缺失 FK、权限及撤销；保留所有历史 ID 和未映射报告。起用前必须在非生产进行弱网、重放、支付未确认、账户停用和故障恢复操作。
5. **回滚**。本 PR 可关闭，或合并后整提交回退。隔离环境丢弃并重建。生产前确定旧版本和恢复点，失败先停切换和新写入、保全审计/Outbox，在新隔离目标恢复核对后按批准的兼容前向修正或官方回滚。禁止为回滚而删除有新事实的表，禁止重放未验签支付。

# V4.1 学院、排班及门店设备契约

范围为 BSV1 基础经营闭环。所有下表新增事实在隔离 `identity.A` 的 V4.1 前向修订中验证，正式 CloudBase 无写入或迁移。

| 对象及现有权威 | 隔离记录 | 边界 |
|---|---|---|
| `tr_code`、任职和 EMP/BM · workforce | 复用 `bsv_identity_people`、既有任职及授权记录 | 课程、班次、POS 终端不发人员号。EMP/BM 继续派生。同一人为跨店范围的唯一主体 |
| `course_id`、版本、学习、尝试 · learning | `bsv_learning_courses`、`bsv_learning_course_versions`、`bsv_learning_enrollments`、`bsv_learning_attempts` | 课程以 ID 加版本发布。题目答案仅服务端评分。已完成学习、理论通过分别记录 |
| 实操、`credential_id`、课件 · learning | `bsv_learning_practical_reviews`、`bsv_learning_credentials`、`bsv_learning_assets` | 本人不能签发。资格引用实际考试与实操，并随课程版本、证据完整性、有效期和撤销重算。个人及媒体状态由受控 API 返回 |
| `shift_id` · workforce | `bsv_workforce_shift_assignments` | 指定法人、门店和岗位。存时区及带偏移时间。员工确认前不允许点单。失去资格的已排班记录投影为待重排 |
| `store_id`、`legal_entity_id` · organization | 复用已登记门店和隔离法人范围 | 隔离试点仅 BSVT、BSVS。合作门店和未经核实的门店默认拒绝 |
| `device_id` · identity_access | `bsv_identity_store_devices` | 指定门店和撤销状态。注册密钥仅首次返回，存储校验摘要。POS 按当前统一会话和权威设备检查 |
| `order_id` · commerce | 复用 POS SQLite 订单及审计 | 订单保留实际 TR、设备、当班和岗位。SQLite 人员投影供既有本地外键使用，不能用于发 TR 或批准任职。旧码映射逐条核实 |

## 数据与迁移边界

隔离版本 `bsv_academy_0002` 追加结构，保留 V3 数据和旧外键。发布先验证备份，代码回退保留追加数据。正式数据迁移使用另行批准的 CloudBase 官方账本，暂未执行。

以下条件须同时有效才能在 POS 写订单。统一会话、现行任职和 EMP 资格、通用理论、本店培训及独立实操、现行门店岗位授权、当前已批准并确认的班次，以及本店已登记设备。服务不可用时停止当前写入。已保存请求可按准确的幂等键再次核对。客户端在结果未确认时不得宣称成功。

## 课件与真实导入

本地隔离课件目录仅供已授权用户。未配置可用扫描器时上传须失败关闭。内容进入受控私有路径，记录文件摘要、类型和权利引用。版权、个人信息、储存保留周期及真实用户访问批准是独立正式门禁。合成测试不得复用真实源数据。

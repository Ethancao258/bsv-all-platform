# Identity API｜错误码、幂等与超时契约

完整契约：`identity.openapi.json`，由 `scripts/export_contracts.py` 从实际 FastAPI 路由导出；主入口 `/api/v1/identity/`。

| HTTP | 业务含义 | 调用策略 |
|---|---|---|
| 201 / 202 | 测试注册成功 / 永久 TR 报名申请进入待审；阶段/授权申请已受理 | 不等于正式发码或有权限；请求方记录服务器返回 `request_id` |
| 400 / 422 | 字段错误、非法作用域、能力前置条件不满足 | 客户端展示字段原因，不应自动重试产生新申请 |
| 401 | 缺少有效个人登录或服务身份凭据 | 退出敏感界面、重新登录；不暴露服务端密钥 |
| 403 | 未被授权、当前法人/门店/动作被拒、CSRF/Origin 拒绝 | 停止执行；不要凭 EMP/BM 字符串自行放行 |
| 404 | 不在作用域或资源未找到 | 不以不同细节泄露是否存在其他法人自然人 |
| 409 | 状态冲突、重复申请/重复 idempotency、非独立审批、对象历史已存在 | 根据错误消息走人工审核或读取已有申请 |
| 429 | 隔离环境单 worker 限流 | 等待后重试；真实生产必须由可信网关补充分布式限制 |
| 503 | 数据库 A、永久码 allocator/认证配置不可用 | **拒绝授权**，停止敏感写操作；不能从 B/LOCAL 继续审批 |

**幂等契约**：同一个认证主体提交同一个 `idempotency_key` 和**完全一致** payload 返回同一报名记录；相同键+不同 payload 返回 409。独立审批可能再次提交已审批 request_id，但服务器只存在一个 TR 与阶段唯一约束，失败时事务回滚；网络连接失败不得自行换新幂等键。客户端推荐对网络超时使用指数退避+jitter，原键不变；对独立审批仅人工检查后重试。

**服务间权限 API**：`POST /api/v1/identity/authorize` 仅允许服务端带 `X-BSV-Service-ID` 与 `X-BSV-Service-Token` 请求；工作前重新检查法人/门店/资格有效性，响应 `allowed`，`cache_ttl_seconds=0`。正式 Token 使用既有认证服务或可信内部身份替代并建立轮换；浏览器不得获得该凭证。

**变更原则**：所有不兼容请求/响应结构更改应另增 `/api/v2`，不能在现有 POS、供货模块未更新时直接改契约；API 版本和迁移兼容性须通过主仓集成测试。

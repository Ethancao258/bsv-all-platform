# 原始资料批量接入、数据导入与来源保全

**禁止直接把Excel列名当作数据库主键或实时表字段。**

0. **发现与索引**：列出当前所有正式/历史/草案资料及程序，登记版本、来源、上传人、实际SHA256、文件长度、内容类型、数据敏感级别、使用许可和拟定归属域。程序旧版仅当“待审历史来源”。
1. **原件不可变**：真实原始文件保存在受控私有存储；Git仅提交脱敏清单和映射规则，不提交会员PII/员工合同/薪酬明细/收银资金信息。所有来源可追溯到对象存储URI或内部文件号，不把原文件字节上载到公开源仓库。
2. **解析到staging**：每个来源定义机器可读 schema、字段类型、单位、时区、唯一ID映射、缺失值规则和加工算法，不直接写正式表。
3. **校验和冲突隔离**：必核查重复ID、名/码混淆、负数库存、资金口径、权限范围、缺失来源、版权、产品上架资格；不确定项进入 quarantine，有负责人和处理记录。
4. **人工批准与受控发布**：通过对照、数据行数/金额/哈希/抽样，先测试环境 dry-run，再在备份可恢复的条件下按官方迁移/受控导入API执行；财务/支付等高危数据需专项审计批准。
5. **版本/回退**：每批有不可变 `import_batch_id`、源SHA、映射版本、代码Git SHA、作用门店、结果计数、异常计数、审批人；已落库事实纠错不无痕删除。

## 推荐导入顺序

1. 现有10产品表**先只读核验**，读取真实Schema、映射历史、错列和导入证据；不可再次盲目全量导入。
2. `organization` 门店及法律主体和 `identity_access` 员工权限基础（仅在授权与用工资料合规时）。
3. `knowledge` 现有公司SOP、培训资料和公开链接；`learning` 课程+考核+认证，不保存未授权教学资源全文。
4. `commerce` 旧订单/门店本地SQLite，历史资金状态待核对，禁止凭员工录入标PAID。
5. `catalog` 菜单已批准版本、`inventory` 产品物料、采购、中央生产标签与配送。
6. `customer` 经合法授权的会员、`marketing` 真实活动触点。
7. `operating_finance` 历史经营费用、薪资和分润；直营与合作利润归属分离。
8. `quality` 督查整改、`partnership` 外部合同、`capital` 合规审议记录。

模板：`ingestion/templates/import-batch.example.json`。新格式在 `ingestion/mappings/` 下扩展，不建临时的第二主库。
